# Uncordex unsigned package plan

Owner: installer task, GPT-5.6 Luna / max. Coordinator: parent task.
Dependency: GUI completion and explicit coordinator approval of its bundle contract.

## Gate

Initially read this plan and report readiness only. Do not implement, build, modify files, or redesign GUI/service interfaces until the coordinator sends `GUI APPROVED` with the reviewed source snapshot and `gui-handoff.md`. Work from that supplied snapshot, not a stale branch or an unreviewed shared build directory.

## Deliverable and behavior

Produce an unsigned macOS Installer `.pkg` supporting macOS 13.0 and later on Apple Silicon and Intel. Install the approved `Uncordex.app` into `/Applications/Uncordex.app`. The package installs files only: no root-launched GUI, service bootstrap, Bluetooth calls, Homebrew installation, console-user guessing, or per-user config writes. First-launch app setup runs explicitly as each logged-in user. Explain this in Installer text and documentation.

Keep blueutil external as defined by the approved app. Include first-party license and third-party notices. Preserve existing user configuration, state, logs, and LaunchAgents on app installation/upgrade. The running service uses its existing per-user staged files; explain that applying setup in the updated app updates that service payload. No migration to a system daemon.

## Implementation steps after approval

1. Inspect the approved app handoff and build script. Verify available Apple packaging tools and their flags. Consume the approved app build; do not redesign or edit app/service behavior.
2. Add `packaging/` with build script and Installer resources. Use pkgbuild/productbuild, a stable package identifier (`uk.magrathean.uncordex.pkg`), VERSION-derived version, minimum OS 13.0, and both supported architectures. Disable unintended bundle relocation so an old app in another folder is not selected as the installation target.
3. Stage only the approved bundle at `Applications/Uncordex.app`; preserve permissions and validate required payload resources. Fail clearly on a missing/invalid bundle, wrong architectures, unsupported deployment target, or malformed version. No privileged install scripts are expected.
4. Emit `/Users/test/dev/build/uncordex/pkg/Uncordex-<version>.pkg`. Keep staging, expansion, caches, temporary files, test fixtures, and logs in that task's build directory. Set TMPDIR and tool-specific paths; do not repurpose HOME or CODEX_HOME. Rebuild from source reproducibly using the approved GUI build command and a task-specific output directory when supported.
5. Verify with package expansion and metadata/payload inspection, without installing on this Mac. Check payload paths, identifier/version, minimum OS, architecture declarations, app bundle metadata, executable modes, resource completeness, absence of activation scripts, and expected unsigned status. Add focused packaging validation tests, including rejection cases, without mocking away the validation being tested.
6. Write `docs/pkg.md` with build command, artifact path, unsigned-package opening instructions, dependency/first-launch flow, upgrade behavior, and removal guidance that preserves user data. Do not recommend disabling Gatekeeper globally. Run repository-required checks with substituted boundaries and TMPDIR under the package build directory.
7. Report changed files, artifact checksum, verification evidence, and manual acceptance checklist to coordinator. Stop for review. Physical installation/upgrade acceptance on macOS 13 Intel and Apple Silicon remains explicit manual work unless separately authorized.

## Ownership and coordination

Installer task owns `packaging/` and `docs/pkg.md` only. Ask the coordinator for contract changes or shared documentation integration. Do not edit `app/`, watcher/service scripts, tests/run.sh, GUI plans, VERSION, or release files. Do not message the GUI task. No local commits, real installation, publishing, tags, or releases.

## Coordinator acceptance

Review diff, independently inspect expanded package under `/Users/test/dev/build/uncordex/review/`, verify it contains the approved app, request corrections as necessary, and integrate only reviewed changes. Parent owns README/documentation links and overall completion report. Distinguish successful build/static inspection from physical installation acceptance.
