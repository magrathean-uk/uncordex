# Uncordex macOS app plan

Owner: GUI task, GPT-5.6 Sol / high. Coordinator: parent task.
Order: implement and pass coordinator review before package implementation begins.

## Deliverable and scope

Build a small native `Uncordex.app` with AppKit and Swift, targeting macOS 13.0 on arm64 and x86_64. Use Swift language mode 5 where practical and verify every API against the deployment target. No SwiftUI, external UI frameworks, privileged helper, or replacement watcher. A compact standard window is sufficient; a menu-bar companion is optional only if it adds little complexity.

The window should show service availability, configured speaker, saved rule, latest observed power/source, retry status, and clear missing-dependency or configuration errors. Distinguish cached watcher observations from current readings. Offer paired-speaker selection (with manual address fallback), read-only source discovery, explicit selection among saved source / any power / disconnect only, preview and apply setup, start/stop the canonical service, refresh, and open logs. Quitting the app must leave the service running. Do not equate the watcher's `paused` retry phase with a user-stopped service.

Keep blueutil as the existing external dependency for this first version. Detect both Homebrew locations and show actionable setup instructions when absent. Never silently install Homebrew or blueutil. No direct connect/disconnect buttons, automatic pairing, radio toggles, or automatic service activation on first launch.

## Implementation steps

1. Inspect AGENTS.md and existing setup/status/test interfaces. Verify macOS 13 API availability using primary Apple documentation as needed.
2. Define a small testable process/service adapter. Use explicit executable paths and argument arrays, never interpolate user input into shell code. Run subprocesses off the UI thread, drain both pipes, bound execution, handle errors, and prevent overlapping mutations. Treat configuration as data in Swift; do not attempt to parse arbitrary shell quoting by hand.
3. Reuse install.sh and watch-power interfaces. Add a narrow versioned machine-readable interface under the GUI task's ownership if needed for reliable status/configuration/discovery; retain current CLI behavior. Preserve service ownership, rollback, paths, and fail-closed restoration rules. A stopped service must not be reported as running based only on persisted state. Do not launch a second watcher from the app.
4. Build the accessible AppKit window, sensible empty/loading/error states, keyboard navigation, and light/dark appearance. Applying configuration must show the selected behavior and use the existing installer as the logged-in user. Stopping must retain configuration and state; starting must use the canonical LaunchAgent.
5. Add a reproducible command-line build under `app/`, with source and resources there. Emit a universal app at `/Users/test/dev/build/uncordex/gui/Uncordex.app`. Bundle install.sh, uninstall.sh, watch-power, lib/source.sh, VERSION, LICENSE, and THIRD_PARTY_NOTICES.md under `Contents/Resources/Service/`, retaining relative layout. Establish identifier `uk.magrathean.uncordex`, minimum OS 13.0, version from VERSION, and executable permissions. Ad-hoc signing is acceptable for local launch; no developer certificate requirement.
6. Add focused adapter/UI-model tests with fake subprocess boundaries. Verify missing dependency, malformed/missing state, discovery failure, setup failure, stop/start, and no mutation on launch/refresh/quit. Build both architectures; inspect binary slices and minimum OS metadata. Inspect UI using a fixture/demo mode that cannot operate real hardware or LaunchAgents.
7. Run repository-required Bash syntax checks, simulated suite, and ShellCheck if installed after final edits. Record separate native build, simulated, visual, and physical acceptance evidence. Do not claim macOS 13 runtime acceptance from deployment metadata alone.
8. Write `docs/app.md` and `docs/plans/gui-handoff.md`: exact build/test commands, reviewed artifact layout, interface contract, changed files, limitations, and evidence. Report checkout path to coordinator and stop for review.

## Ownership and boundaries

GUI task owns `app/`, `docs/app.md`, `docs/plans/gui-handoff.md`, and narrowly required service/test changes. It must not create packaging code, change the package plan, or edit release/version files. Coordinate any shared-file concern through the parent; do not message the installer task. No commits, installation on the real user account, publishing, tags, or releases.

All generated builds, caches, module caches, derived data, temporary test roots, and logs must stay under `/Users/test/dev/build/uncordex/gui/`. Set TMPDIR and tool-specific cache/output flags before builds/tests; do not repurpose HOME or CODEX_HOME. Keep source in the task checkout. Never edit `.serena/`.

## Coordinator acceptance gate

Review the complete diff and process boundaries; reproduce focused checks with outputs under the review build directory; inspect fixture UI and verify the universal bundle contract. Resolve defects in the GUI task. Only then integrate its reviewed changes and provide the installer task an exact approved source snapshot and handoff.
